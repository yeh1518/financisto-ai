# 掃圖記帳——v1 定稿（2026-07-29）

> **接手本專案的 session 一律以繁體中文回應與產出。**
>
> 擴想收斂結果：**QR 與 OCR 不做成兩個模式，而是同一次取像的兩個來源**，在欄位層級合併。
> 模式化會產生兩個症狀——系統自動搶模式（使用者本來想 OCR，畫面有 QR 就被跳走）、
> 以及不夠用時要手動再跑另一條（QR 資訊不足要補 OCR）。取消模式，兩個症狀一起消失。

## 核心原則

**確定的用規則，模糊的交給 LLM。** QR 給準確骨架（日期／金額／統編），OCR 給文字線索
（品項／商家），LLM 只負責判斷分類這類本來就沒有標準答案的欄位。

## 使用者流程

```
相機頁（App 內，CameraX 預覽）
  ├─ 背景持續偵測 QR；掃到 → 底部浮出「建議條」：電子發票 · $250 · 7/29 · 點此直接記
  │    └─ 點建議條 ＝ 快路徑：不拍照、不 OCR、當場成交易確認頁
  └─ 按快門 ＝ 完整路徑：同一幀同時跑 QR decode + 本機 OCR
        └─ 欄位合併 → 送 LLM 補分類 → 交易確認頁（原生 TransactionActivity，同語音那條）
```

**建議條只做建議、不自動執行**——系統永遠不搶方向盤，只把捷徑放在手邊。
**快門是主要動作、永遠可按**：沒有 QR 的收據是常態不是例外（餐廳帳單、傳統手開發票、
國外收據、只印簡易明細的店家），UI 不能長得像「QR 為主、OCR 是備援」。

## 欄位合併規則（寫死，不由 LLM 決定）

| 欄位 | 取用順序 | 備註 |
|---|---|---|
| 金額 | QR 總計額 → OCR 數字 | 兩者差異過大就提示（多半是拍到隔壁張或抓到找零欄） |
| 日期 | QR（民國轉西元）→ OCR → 今天 | |
| 商家 | 統編 → OCR 抬頭行 | 統編是最乾淨的 key：機器產生、唯一、零變體 |
| 分類 | LLM 當場判斷（線索＝品項＋商家） | **不記憶**，理由見下 |

## 已拍板的決定

| 決定 | 內容 |
|---|---|
| 取像 | **App 內相機為主**（紙本發票的情境是站在櫃檯前，先拍照再分享太繞）；分享／選相簿保留為第二路，處理截圖用 |
| 解析路徑 | QR（deterministic）＋ 本機 OCR，**不做圖直送 vision 模型**——前兩者涵蓋得了，且省 token、可離線 |
| 離線 | QR 與 OCR 都在本機跑，只有補分類要連網。沒訊號時存成待補完 draft，有網再補——掃的當下不會卡住 |
| 留圖 | 做成設定（關／7 天／永久）。存 app 私有 filesDir，壓縮後 JPEG（長邊 1600、質量 70）而非原檔。初期預設開＝debug 需要看得到現場；**快路徑（沒按快門）也存一張當幀**，否則出錯時手上沒有任何證據 |
| 確認 | 沿用語音那條的收尾：預填原生交易頁讓使用者過目按存，不靜默寫入 |
| 入口 | AI 輸入頁在大麥克風下方加一顆次級相機鈕（浮動鈕的手勢已滿：點＝主動作、長按＝設定、拖曳＝移位，不再加第三種）；另做「掃發票」桌面捷徑 + 1x1 widget，比照語音那組 |

## v1 明確不做

- **商家 → 分類學習表**：擴想後否決。它本質上是「自動產生的樣板」，跟因投報率被擱置的
  通知樣板是同一種東西；而它省下的是 API 費（用免費額度、不是問題）與重複手按（成本本來就低）。
  改成**先蒐證、不建制度**：v1 只記軌跡（統編／商家、最終分類、是否被使用者改過），
  跑一兩個月後看真實數據——集中度高才值得做表，數據若顯示本來就不一致，這表就不該存在。
  代價只有多記幾個欄位，兩種結論都不虧。詳見 [[通知樣板解析-定稿]] 的未來 TODO 節。
- **一張發票拆多筆分類**（買菜＋日用品）：靠品項明細拆帳，v2。v1 記總額。
- **連續掃一疊**：v1 單張，但按鈕位置先留。
- **語音路徑接學習/記憶機制**：STT 輸出本質不穩定（同一句話每次辨識有細微差異），
  拿它當 key 會把最不穩定的來源引進最穩定的地方。語音永遠只走「當場判斷」。

## 技術選型

- **相機**：CameraX（預覽 + ImageAnalysis 同時跑 QR 偵測，按快門才取一張高解析度幀）
- **QR**：電子發票左碼 QR 為固定格式——發票號碼、開立日期（民國）、隨機碼、銷售額與總計額
  （16 進位）、買賣方統編、加密驗證碼。這段可靠。
  ⚠️ **品項明細接在後面、可能溢到右碼，但各家 POS 印不印、怎麼編碼並不一致**——
  實作前先拿數張真發票實測涵蓋率，決定分類線索能不能靠它。
- **OCR**：ML Kit 文字辨識（中文模型）。**選 bundled 而非依賴 Play Services 下載**：
  APK 約增 5MB（現 24MB），換到「永遠離線可用、無首次下載延遲、不綁 Play Services」。
- **補分類模型**：沿用解析鏈既有 provider 設定（預設 gemini-3.1-flash-lite）。
